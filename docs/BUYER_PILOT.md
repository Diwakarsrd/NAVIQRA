# NAVIQRA strategic buyer pilot

## Pilot proposal
Run a 4–6 week, sandbox-first integration with a travel marketplace or accommodation platform.

## Scope
- Embed the NAVIQRA agent runtime behind the buyer's existing identity and API gateway.
- Import a consented, minimized traveler preference profile.
- Use graph context and five-tier memory to personalize destination and stay discovery.
- Use group consensus to rank a shortlist for multi-traveler trips.
- Simulate disruption recovery with human approval and supplier sandbox APIs.
- Evaluate all outputs against buyer-approved test cases and a current baseline.

## Success measures
Agree baselines and thresholds with the partner before the pilot. Candidate measures include time to shortlist, preference match rate, group decision time, grounded answer rate, recovery recommendation acceptance, API latency, cost per successful task, and rate of unsafe or unsupported actions.

## Safety and data boundaries
The pilot must use synthetic or explicitly consented test data. Do not ingest payment card data, passport numbers, or special-category personal data. Do not initiate live purchases. The partner retains control of identity, user consent, supplier contracts, payments and customer support.

## Exit criteria
A signed evaluation report, reproducible benchmark artifacts, security review, integration documentation, and a commercial proposal. A pilot is not an acquisition commitment.
